# SO2 击杀集锦

用户提供输入和提取目标后，当前 AI 自主完成到交付：后台按播报画面和当前视角给出候选，AI 看图判断、补漏、修正回合范围和武器，工具执行最终清单并校验。默认不用预填游戏 ID，名字只作辅助。阶段之间不等待用户说“继续”，不把逐条复核交给用户。无法确认的内容不进入正式成片，可靠部分交付，整批标部分完成并说明缺口。质量优先；无新进展时停止无效重试，继续独立项。扫描完成、内容确认、文件校验、实际播放／试听和用户验收分别记录。

## 入口与路由

所有命令从本 Skill 目录定位 `scripts/clip.ps1`，不要依赖工作目录、开发者盘符或 PATH 中未确认的 Python。

| 当前需求 | 执行动作 | 按需阅读 |
|---|---|---|
| 首次使用、缺依赖或 GPU 故障 | `doctor`；缺运行配置时启动用户级安装 | [安装](references/setup.md) |
| 新素材或布局变化 | `inspect --input <路径>`，查看返回的代表画面 | [校准](references/calibration.md) |
| 批量提取、全量整理多杀素材 | status → 增量扫描 → prepare → evidence → AI 决定 → deliver → 成片看图回填 → deliver | [自主交付](references/delivery.md)、[内容判断](references/workflow.md) |
| 已交付片段只需按武器分类 | 新清单直接修改分类映射并 deliver，复用字节；历史清单先核对映射 | [自主交付](references/delivery.md)、[分类与移动](references/workflow.md#5-分类移动与交付验证) |
| 已交付素材重复、漏杀、杀数不对、前后没接上或片尾截断 | 从当前交付反查源区间和缓存；局部复核后按修订清单重提 | [快速返修](references/workflow.md#快速返修已有素材) |
| 普通提取、调节上下文或可选合并 | 共用下方主流程 | 无需额外加载 |
| 疑点、延迟击杀、误报、时间位置不对 | 核对实际源画面，再提交有证据的复核结论 | [复核](references/review.md) |
| 中断、缓存、损坏输出、失败重试 | 先查活跃进程和当前修订清单，再决定复用或重跑 | [恢复](references/recovery.md) |
| 教程、口播、封面、其他游戏 | 说明此 Skill 的范围；使用适合该任务的能力 | 不启动此扫描器 |

## 共用主流程

1. 继承本任务已确认的输入、人物、输出位置、分类和交互限制，最新要求覆盖冲突项。未指定人物时取当前视角全部人物；昵称读不清但视觉击杀和连续归属已确认时，用扫描返回的稳定匿名标识保留片段。指定人物须核对确切名字及对应视角，匿名不能当作目标命中。批量提取／整理多杀素材未另指定时，采用同人物、同回合完整多杀与武器大类文件夹。缺输入才询问路径，其余可合理确定的选项直接采用并说明。详见[任务约定](references/workflow.md#先固定本批交付约定)。
2. 先用 `status --input` 找到当前扫描、首次导出前的 `active_review` 和已交付的 `curated_delivery`。已有清单用 `status --plan` 续办，复用有效决定和产物；补扫后再 prepare 刷新扫描材料并检查新增线索。历史非结构化修订先核对原清单与路径映射。禁止 Computer Use 时用命令行抽帧和直接看图，分别记录播放／试听状态。只覆盖当前 Codex 任务的持续执行和中断后恢复，不新增开机唤起服务。详见[自主交付](references/delivery.md)。
3. 新环境或依赖变化先执行 `doctor`，已有有效自检可复用。缺配置由用户级 `setup.ps1` 安装，严格离线用 `-Offline`。新来源执行 `inspect --input`，查看旋转后的 HUD、阶段和反馈，并按代表布局试跑。发现杀数、时间或片尾不符，先校准再扩大处理范围。时间轴错位按[源时间校准](references/calibration.md#源时间与扫描时间)处理。
4. 大批量使用 `run --scan-only --defer-report-images` 增量扫描，然后 `prepare` 生成源快照和复核队列；指定人物传 `--actors`。工具按视角／阶段生成同回合候选，计数差异与零候选源仍需检查。扫描阶段写盘、报告完成及内容确认分别判断；同一状态目录有系统写入锁。
5. 逐杀联合复核人物、实际杀数、同回合范围、武器与重复。引擎的至少 2 杀、间隔 ≤10 秒、前后各 15 秒用于候选分组。对照首杀前、每次动作和末杀后，按实际人物与回合连续性补齐长间隔击杀，保留交战及必要结局。每杀记录源时间和画面依据，详见[完整工作流](references/workflow.md)。
6. 用 `evidence` 看源图后，在 prepare 返回的 plan 中填写源级检查、疑点处置、逐杀时间／人物／武器／证据、最终范围及去重决定。漏检击杀可直接进入最终 kills，原扫描保留。格式与校验条件见[自主交付](references/delivery.md)。已知候选的引擎事件确认仍可使用 [review](references/review.md)。
7. `deliver --plan` 执行冻结清单、逐项落盘、分类、完整解码和索引更新。随后自行查看 output_reviews 的成片图片，核对首尾及动作，填 confirmed 与实际原因，再次 deliver 复用文件并读回索引。发现错误先修订再重提；出口 3 是当前 Agent 继续复核的信号，不是要求用户接管。占用／冲突保留进度，继续独立项。
8. 读匹配本次 UUID 的 receipt，汇报目录、分类数量、失败／疑点和各阶段证据。可自行解决的问题继续执行；无新证据可解决的缺口以部分完成交付。不把完整解码或静帧复核写成播放／试听或用户验收。缺原扫描总回执保留中断事实；后处理使用自己的新回执。原声合并按需使用原入口。

## 命令

在 PowerShell 中将 `$clip` 设为本 Skill 下 `scripts/clip.ps1` 的绝对路径：

```powershell
& $clip doctor
& $clip inspect --input 'D:\录像'
& $clip run --input 'D:\录像'
& $clip run --input 'D:\录像' --scan-only --defer-report-images
& $clip prepare --input 'D:\录像'
& $clip evidence --plan '<返回的 plan.json>' --clip-id '<实际 clip_id>'
& $clip deliver --plan '<plan.json>'
# 仅在有效缓存和原分组符合复核结论、没有后续人工修订时：
& $clip run --input 'D:\录像' --extract-only
& $clip run --input 'D:\录像\比赛.mkv' --merge
& $clip run --input 'D:\录像' --pre 10 --post 8 --min-kills 3
& $clip run --input 'D:\录像\比赛.mkv' --keywords 'PlayerOne' --identity-mode keywords --profile live
```

其他参数使用 `& $clip run --help` 和引擎实际配置；不要复制文档中的历史参数作为当前真源。手动 `--hits` 跳过 OCR 与热身判定，仅在用户明确提供时间时使用。

## 结果位置与准确性边界

无个人设置时，目录输入保存至 `<素材目录>/output/YYYY-MM-DD/`；单视频输入保存至其父目录的 `output/YYYY-MM-DD/`。日期取电脑当地时区。明确保存的个人输出设置优先，单次 `--output-dir` 优先级最高。

批量素材工作流默认交付为 `YYYY-MM-DD/<武器大类>/*.mp4`，按实际有效类别创建文件夹。普通 CLI 直接提取默认平铺为 `YYYY-MM-DD/*.mp4`，用户指定的布局优先。分类、完整回合整理和路径同步由 Agent 按本批清单完成。扫描记录、日志、报告、断点和疑点截图保存在 `%LOCALAPPDATA%/SO2KillClips/tasks/<输出目录ID>/`，以返回的 `state_dir` 定位。明确要求整理旧输出时，按[恢复](references/recovery.md)迁移辅助资料并保留原文件依据。

自动跳过输出及运行目录。原始录像不上传，不自动清理模型、原件或历史产物。

自动模式看红框内的主击杀位置和文字颜色，结合头像与独立反馈；红框也会出现在死亡、助攻和自杀播报中。回放观战按人物列表的眼睛标记与该人物的击杀数字确认，名字均为辅助。只保留已确认的视觉击杀；严重遮挡、UI 更新、不支持的反馈样式或视角不清进入疑点。昵称模糊与视角归属不明分别处理：前者允许匿名，后者须复核。新增来源的自动匹配记录只属于当前文件修订，不等于长期来源配置。
