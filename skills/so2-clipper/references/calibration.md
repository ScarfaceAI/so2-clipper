# 新来源与布局

`inspect --input` 按每个视频旋转后的实际显示画面分析头像 HUD，保存代表截图和身份校验，返回预设与证据路径。缓存绑定规范化路径、大小和 mtime_ns。相同文件未变时复用；新文件不因同目录或同分辨率直接继承个人身份。

先查看代表图是否为 SO2 简体中文界面。现有 pc、phone、phone-highfps、live 四类布局的播报、阶段和反馈区域由运行时配置定义。带黑边的桌面录屏可能符合 live 几何布局。预设名称描述 HUD 位置，不应按文件后缀或录制设备强行指定。

接近 4:3 一般提示平板来源，较宽比例一般提示手机；用户对本批来源的说明优先。这不是自动选预设的充分条件，也不是比例转换要求。`phone` 是历史预设名，不能据此把 2388×1668 认定为手机。按旋转后的实际 HUD 校准并保留原显示比例，不统一拉伸为 16:9。

自动无法确认时，查看 `tmp/intake/<素材修订>/` 的代表图。若当前 AI 看图能确认属于已有布局，在单文件重试中显式指定 `--profile`；否则保留待复核，继续其余文件。无法确认语言时也不应静默按受支持来源交付。新 UI 或大幅缩放不能通过降低置信度强行套用。

单次指定预设只作用于该次任务。用户明确确认长期来源设置后，可运行：

```powershell
& $clip remember --source 'D:\录像' --profile live --width 1920 --height 1080
```

设置同时绑定目录与显示尺寸，仅用于对应范围。命中已确认来源仍保持视角自动归属，不把一个人的名字套到所有文件。完整长期设置见运行配置旁的 preferences.json。`settings --output-dir <目录> --date-zone local` 保存用户明确指定的输出偏好。

文件内存在不同 HUD 位置、头像不可跟踪或关键提示遮挡时，明确标记对应问题。首版不会凭单张画面把未支持布局标为已验证。对实际机器学习出的别名，范围限定在本文件的连续视角段；另一个文件须重新取得归属依据。

本人游玩检查红框及主杀／受害位置、文字颜色、顶部选中头像和独立反馈；红框本身不代表击杀。带左右人物列表的回放观战检查白色眼睛标记及该行击杀数字，读不清数字时保留未知值，不能当作 0。名字读不清但其他视觉证据已确认时允许匿名；UI 样式、当前视角或动作无法确认时仍待复核。调整这类识别逻辑会使相应自动扫描指纹失效，只在重新选中素材时重扫，不修改原录像或旧成片。

## 源时间与扫描时间

新来源试跑时，对照候选事件时间附近的实际动作、播报和反馈。TS／M2TS 可能有首个可解码帧偏移或时间戳跳变，连续抽帧与按源时间 seek 得到的时间轴可能不同。现有 TS 提前解码策略仍需实际对齐验证。

- 保留扫描原始 `scan_ts` 和源身份。出现偏差时检查首帧时间、容器起始时间、PTS／DTS 及恢复区间，以可见击杀建立 `scan_ts → source_ts` 映射。
- 逐文件、逐适用区间验证映射，至少覆盖区间内多个击杀锚点，并检查跳变或恢复边界两侧。已按源相对时间定位的恢复尾段单独记录，适用区间与连续解码前缀分别确定。
- 将转换规则、适用区间、对齐锚点和复核结论写入本批修订清单。证据抽帧、完整回合判断和裁切都使用已验证的源时间，原始扫描记录继续保留。
- 当前工具无法消除的错位进入待复核。本次测得的偏移只适用于对应源修订及区间，新素材重新取得时间依据。
