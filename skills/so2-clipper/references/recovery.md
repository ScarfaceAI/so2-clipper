# 恢复与回执

先查当前回执、活跃进程与最终修订，再决定是否重跑原命令。普通未人工修订的任务只处理当前选中的素材；扫描失败会重试，合法零击杀可缓存。每个视频成功写入扫描结果后清理其断点；分段恢复重叠回看并共享去重。提取失败不删除成功扫描。

交付布局按当前任务的最终清单恢复，批量工作流默认武器子文件夹，普通 CLI 直接提取默认日期下平铺。运行目录由返回的 `state_dir` 定位，默认为 `%LOCALAPPDATA%/SO2KillClips/tasks/<输出目录ID>/`。`scan_results.json` 保存逐素材状态，`tmp/` 保存断点和布局证据，`runs/<run_id>/` 保存本次日志、回执、清单和必要截图。`--state-dir` 可覆盖运行目录，须与交付目录分开。目录输入递归跳过输出及运行目录。不同目录的同名文件有独立 ID，源文件大小或 mtime_ns 改变时重新核对其修订。

| 情况 | 下一步 |
|---|---|
| OCR／解码失败 | 核对本次文件错误与 doctor；修正后原命令重跑 |
| 未人工修订的片段损坏或缺失 | 原命令重跑；校验失败的片段自动重提 |
| 已有人工分类、合并、范围或杀数修订 | 验证最新交付清单和路径映射，按修订范围恢复，不能直接按旧组重提 |
| 用户指出重复、漏杀或截断 | 按 [快速返修](workflow.md#快速返修已有素材) 查缓存和局部源帧，不全库重扫 |
| 未人工修订，只调整上下文、最低杀数、间隔或合并 | 复用有效扫描后重新分组和提取 |
| 更换布局、OCR、阶段规则或源修订 | 对应扫描失效，重新扫描该文件 |
| extract-only 缺有效扫描 | 退出未完成；去掉该选项先扫描 |
| 没有清晰可跟踪 HUD、未确认的延迟击杀 | 留在疑点，按复核文档处理 |
| 新 CLI 调用指定了已存在的 run_id | 使用新的 run_id，已有调用回执保留 |
| 分类已移动部分文件，遇到占用或冲突 | 按逐项清单核验已完成项，解除占用后续移剩余项，全部就位再提交当前索引 |
| 安装中断 | 同参数重跑 setup，核验后才写运行配置 |

`run` 的 JSON 输出包含 receipt、run_id 和本次 exit_code。核对文件内 run_id 与调用返回一致；缺回执应报本次未完成，不拿其他任务的成功清单补位。退出码 3 是有待复核，不能称为全数完成；失败文件、疑点与条件过滤分别统计。

保存的 `running` 或 PID 可能过期。要核对实际子进程命令、当前源文件、状态目录和日志更新时间；进程退出但缺匹配完成回执时，按中断处理。后台还在写同一状态目录时，不另开第二个写入者。保留现有有效断点，不通过更换输入路径或状态目录逃避恢复。

## 扫描写盘与汇总中断

引擎逐文件保存完整扫描后会清理对应断点，随后仍可能执行报告和疑点截图。主日志暂时不更新时，核对当前子进程、文件生成变化和逐源状态，区分扫描、提取及汇总阶段。

1. 先核对已保存扫描的源身份、参数指纹、阶段检查和覆盖范围。完整且有效的记录可供后续复核，缺断点也可能表示该源已扫描完成。
2. 进程仍在工作时继续跟踪对应阶段。需要中止时只处理本任务进程，记录中止阶段并保留已保存结果。恢复优先消费有效扫描，对无效或未覆盖的素材段再判断是否需要补扫。
3. 缺原调用的匹配总回执时如实保留中断状态。独立复核、提取或分类使用新的 run_id 与回执，关联原调用及恢复依据，各阶段分别验收。
4. 归档断点或原始候选时，按源身份、参数指纹和覆盖范围保存独立快照，记录是否完整。后来产生的部分前缀单独保存，恢复时选择适用且覆盖充分的版本。
5. 仅在候选资料不完整时，才结合已保存扫描和可明确追溯来源的原日志恢复候选。日志提供检索线索，每条有效击杀仍以源画面确认，漏检事件保存人工依据及原有 ID 状态。

## 已修订交付的续办

查找 `active_review`、`curated_delivery`、分类／修复回执、最终清单和新旧路径映射。prepare 创建时即登记清单，因此首次导出前也能从输入目录续办。以源身份匹配且与实际文件一致的最新修订为准，不以旧 `last_run` 或历史续办段落覆盖它。只改名移动的文件通过映射复用原字节；范围或杀数已修订的文件按最终决定复用／恢复。

新 `deliver` 在逐源扫描条目写入结构化 `curated_delivery`，普通 run／extract-only 会返回该清单指针并跳过旧组提取；当前 Agent 随即用 status／deliver 续办。scan-only 可以更新扫描，原指针保留，旧源身份变化时不能复用旧证据。历史非结构化说明尚未自动迁移，先读最终清单与映射，按[新格式](delivery.md)保存有依据的决定。

补扫后再次 prepare 会保留原清单的决定、证据与历史快照，刷新源扫描材料和新增线索，并要求重新完成源级检查。不能因输入路径相同或清单可复用而忽略补扫结果。

新任务的阶段快照为 runs/<run_id>/status.json，完整扫描范围在报告前写入 scan-stage.json。`--defer-report-images` 将疑点图片留给 evidence 按需生成。快照不代表进程仍然存活，恢复时仍核对真实进程；写入锁在进程退出后自动释放。

不自动清理原件、历史片段、模型或旧记录。旧版记录缺身份校验时，首次选中重扫；原始记录与迁移备份保留。需要清理时按用户明确范围另行处理。

## 整理旧输出

只有用户要求整理旧交付目录时，使用引擎旁的 `organize_output.py --output-dir <交付根目录>` 预览路径，再加 `--apply` 执行已有授权的范围。使用 doctor 返回的 Python 和引擎位置；分享包中的引擎在 `runtime/scripts/`。

整理保留日期下的成片原位，将扫描记录、临时目录、日志、旧报告和疑点资料迁到运行目录。迁移先检查冲突，保留文件哈希和原始文本备份，并修正截图引用；不重新 OCR 或编码。目标已存在时先核对来源，不覆盖新状态。发现旧扫描记录时，引擎会明确提示迁移，避免忽略旧缓存后重复扫描。
