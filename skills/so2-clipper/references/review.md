# 事件复核

先区分“复核已有候选事件”和“修复交付片段”。杀数错误、缺前后击杀、截断、重复及武器分类同时涉及内容与输出范围时，先按 [完整工作流](workflow.md) 核对整段，再决定是否适用下面的事件提交接口。`review` 为空不证明没有漏杀；只查看它列出的时刻也找不到未记录的击杀。

对照本次回执的源路径、事件和清单。`review --input <视频> --output-dir <结果根目录>` 输出当前文件的源身份、扫描指纹、事件 ID、人物视角段和疑点；无有效扫描时先扫描，不能套用历史 last_run。

```powershell
& $clip review --input 'D:\录像\比赛.mkv' --output-dir 'D:\录像\output'
# $stateDir 使用本次 run 返回的 state_dir
& $clip frames --input 'D:\录像\比赛.mkv' --times '80,81,81.5,82' --output (Join-Path $stateDir 'review-evidence\event1')
```

`frames` 从实际源文件提取原尺寸画面，生成 frames.json，记录源身份、时间和图片 SHA-256。查看事件前、首次出现时及之后的画面；只看播报截图不能证明当前视角归属。判断当前头像、开火或投掷动作、独立击杀反馈、播报左右方向、受害者与去重。助攻、自杀、别人的击杀不能计入。

红框表示这条播报涉及本人，还须区分主杀、助攻、受害和自杀；白色武器、爆头或致盲图标不能当成白色名字。本人游玩结合当前头像和独立击杀反馈；回放观战查看人物列表中眼睛选中的人物及该行数字的连续增长。单次增长超过 1 且缺少各次动作时，不凭空补出多个击杀时间。

名字只作辅助，相似名字不能自动当作同一人。默认全人物时，昵称模糊但视觉击杀和归属已确认可以用稳定匿名标识；指定名字时则须补足身份依据。像素行的连续跟踪确定首次出现时间，后面才读清的名字不另算一杀。现有计数不是新击杀。短源片首帧已带的历史计数不计作新击杀；切到 B 后保留的 A 旧播报不是 B 的击杀。计数与播报不一致时查动作，不能直接拿末端 HUD 数字覆盖文件名。

延迟击杀要同时看 A 的先前动作、A→B 切换和之后的实际结果。只有足够证据证明动作属于 A，才可归 A 的原视角段。关联不超过 10 秒且不跨热身或阶段不明区间，B 的击杀仍独立。缺原动作画面时不确认。

复核 JSON 格式如下，字段取自 `review` 和实际 `frames.json`，不要抄示例中的占位值：

```json
{
  "source_identity": {"path": "规范化源路径", "size": 123, "mtime_ns": 456},
  "scan_fingerprint": "对应当前扫描指纹",
  "evidence_manifest": "<state_dir>/review-evidence/event1/frames.json",
  "decisions": [{
    "event_id": "实际疑点ID", "action": "confirm", "view_id": "原视角段ID",
    "killer": "画面中的杀者", "victim": "画面中的受害者",
    "reason": "具体可见的动作、归属及结果依据",
    "evidence": ["实际事件前图片路径", "实际结果图片路径"],
    "delayed": false, "action_ts": 81.0
  }]
}
```

排除事件用 `action=reject`，仍需实际画面和具体原因。确认事件需要事件前后画面；延迟事件还需要距 action_ts 不超过 0.5 秒的原动作画面。引擎核验当前源修订、扫描指纹、图片哈希、视角与阶段边界后才更新。原结论、证据和变更保存在 review_history，重复提交同一结论幂等。

```powershell
& $clip run --input 'D:\录像\比赛.mkv' --output-dir 'D:\录像\output' --extract-only --decisions 'D:\复核.json'
```

此接口受已有候选、视角和阶段约束。缓存中完全没有的击杀或错误视角终点，使用[自主交付清单](delivery.md)的 kills 和最终 start/end 修订；不要伪造候选 ID，也不要假设事件提交成功后旧分组会自动变成完整回合。生成源图和成片图、内容决定与导出后的核对都由当前 Agent 完成。

新视觉扫描中，已实际看图确认击杀但昵称读不清时，`confirm` 决定可写 `"visual_confirmed": true` 并省略 killer／victim。仍须有效视角、事件前后图片、具体原因及合法阶段；此方式沿用视角的匿名标识或已确认身份，不会凭模糊名字添加别名。指定人物的最终交付仍检查名字依据。旧名字模式继续要求读清杀者与受害者。

缺少可靠视角段或未验证布局时，先解决校准问题；复核文件不能凭空创建已经验证的自动结果。严格离线而当前工具不能看图时，保留疑点，不调用另一个收费服务。媒体校验通过与实际播放／试听分开记录。
