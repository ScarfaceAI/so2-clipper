# 完整交付与快速返修

用于大批素材、武器分类和已有片段返修。下面的画面判断由当前 Agent 自主完成。通用清单执行、证据准备和续办命令见[自主交付](delivery.md)；工具生成候选、派生武器目录并执行决定，人物、完整回合、漏杀和跨源画面重复仍须 Agent 看图确认。

## 先固定本批交付约定

从对话和当前交付记录继承已确认条件。用户追加指定人物、完整回合或分类要求时，更新冲突项并继续执行。批量提取／整理多杀素材未另指定时，以同人物、同回合的完整多杀为目标，按武器大类建文件夹。用户要求短连杀、平铺或其他分类时采用对应约定。只询问会改变执行且无法从现有资料确定的缺口。

| 条件 | 必须落到什么结果 |
|---|---|
| 输入、输出、处理范围 | 源文件清单与身份；不把输出或备份再次当输入 |
| 内容范围 | 短间隔连杀，或保留同人物同回合的完整表现；不能默认为二者相同 |
| 最低杀数 | 是否保留单杀；返修已有交付不因默认至少 2 杀而擅自丢弃既有单杀 |
| 武器分类 | 用户给定的类别、跨类别击杀规则、无法覆盖的武器如何处理 |
| 目录与文件名 | 明确是否要各武器子文件夹；文件名包含类别、实际杀数、来源、源区间及短唯一标识 |
| 原比例、声音 | 保留旋转后的显示比例和原音轨，不按设备猜测后拉伸 |
| 后台与通知 | 本机进程、聊天续办和自动通知是三件事；按用户已授权的方式执行 |

人物范围记录为“当前视角全部人物”或“指定人物集合”，默认前者。自行游玩与观战均按视觉证据确认当前人物。昵称模糊但主击杀角色、连续视角和杀数已确认时，保留扫描返回的 `视角人物_<标识>`，逐杀与片段使用同一标识，不擅自补名字。指定人物仍须验证确切名字与对应视角，匿名片段不能自动通过筛选。`identity-mode=auto` 提供归属线索，指定目标的交付筛选由 Agent 完成。具体名字、昵称变体和本机路径保持在本批记录中。观战时，红框描述录像拥有者的参与；当前观战人物由眼睛标记确认。即使录像拥有者只获得助攻，只要眼睛选中的队友完成击杀，也应归到该队友视角。观战人物的名字须对照选中人物栏确认，不能拿同时出现的第三方播报名替换匿名标识。

默认按武器大类整理为狙击枪、步枪、冲锋枪、手枪、霰弹枪、投掷物、近战、混合，创建有有效成片的类别。用户已有名称时保留该任务的命名，并将同义类别统一映射。每杀按完成击杀的武器归类，同类别内换枪仍归该类别，跑图切刀或末尾拿出其他枪只作为上下文。跨类别有效击杀归混合，纯投掷物或纯刀杀分别归投掷物、近战。无法确认的武器保留待复核。

交互限制也随任务继承。用户禁止 Computer Use 时，通过文件读取、FFmpeg 抽帧与直接查看图片完成校准和内容复核，实际播放／试听按已取得的证据记录。

## 从输入到交付

### 1. 盘点、校准与试跑

- 记录原路径、大小、mtime_ns、显示尺寸、旋转、帧率、时长和音轨。按 HUD 布局、编码和长短素材分组取代表样本，复用同一文件身份的抽帧和校准结果。
- 接近 4:3 通常提示平板来源，偏宽屏通常提示手机；这只是来源线索。预设名 `phone` 是历史名称，实际区域由画面决定。
- 先检查代表原片的开始、交战和结束，再试跑合适的短原片。不要通过复制或裁出临时文件测试缓存复用，改变源身份会失去原缓存。
- 对照真实可见击杀与输出。已经识别到多次击杀却没有片段、末杀出现在边界外、HUD 与播报不一致，都是全量处理前需要解释的信号。确认布局不等于确认内容完整。
- 代表击杀需与源时间对齐。TS 首帧或时间戳跳变造成错位时，先按[源时间校准](calibration.md#源时间与扫描时间)建立逐源、逐段映射，再生成复核图和裁切范围。

### 2. 扫描与队列

- 大批分类优先先 `--scan-only`，读取逐次匹配回执，再复核和集中编码。小任务可直接 `run` 生成候选；候选通过文件检查后仍需内容复核。
- 共享 `state_dir` 同时只保留一个引擎写入者。分类决定可另存，不能趁扫描写入时改共享缓存或移动它仍在使用的输出。
- 续办同时检查实际子进程、命令所指输入／状态目录、日志更新时间、匹配回执与断点。保存的 `running`、PID 数字或启动器存在均不能单独证明在运行。
- 扫描逐文件写盘后还可能生成报告和疑点截图。结合完整覆盖记录、子进程、当前输出文件变化判断实际阶段，按[恢复规则](recovery.md#扫描写盘与汇总中断)处置日志暂时不更新、缺总回执和后处理恢复。
- 恢复有效源身份、扫描指纹和断点；仅对失效或失败文件重试。分类、移动、边界调整不改变 OCR 参数。未知布局不能记为零击杀。
- ETA 使用同类编码／布局的已测处理速度和剩余视频时长，给范围；另计复核、编码与校验。不能按文件数线性估算长短混合批次，也不能把扫描 ETA 当最终交付 ETA。
- 进度应写“扫描完成／分类待复核”等实际阶段。用户选择自行回来检查时，不创建自动续办或通知；本机队列也不会自行完成 AI 视觉分类。

### 3. 一次复核四件事：杀数、完整范围、武器、重复

从缓存事件、视角段、阶段信息和疑点生成候选，不只检查 `review` 列表。即使列表为空，也可能漏了缓存之外的击杀。

**杀数与归属**：逐次核对当前人物的动作、反馈、播报和受害者。HUD 总数用来找差异，不能直接写进文件名。短源文件开头若已带一杀但没有其发生过程，不把它算作本片的新击杀；也不能对所有疑似片段统一加一。旧播报残留、OCR 名字变体、自杀、助攻和他人击杀需分别判断。仅末端总数不足时，按时间查找计数跳变及对应播报。

**完整范围**：核对首杀前和末杀后。默认 10 秒阈值只是候选分组，同回合长间隔击杀通过人工范围修订接回。先复核从首个候选到回合结局的上下文，再查其中未被扫描记录的动作。练习中的复活、回合重置和真实切人要断开。补上下文后的区间重叠只作为重复线索，按实际击杀和人物、回合连续性决定是否合并。缺头像、闪光和记分板先作为可疑边界检查，阵亡互换时核对击杀与死亡的先后。首杀前通常保留约定的 15 秒，末杀后结合胜负、拆包、爆炸或死亡结果决定必要收尾，并在下一回合或切至他人视角前结束。拆包失败被 C4 炸死按结局保留，自杀不计入有效击杀。源文件本身结束时记录范围限制。

**武器**：按每次完成击杀时的武器和播报图标判断。中间持枪、跑图切刀或片尾换枪不能代表所有击杀。先修正事件与范围，再确定分类，避免补回一杀后文件夹却仍沿用旧类别。未知保留待复核，不作为混合交付。

**重复**：检查同源区间和跨源长短版。文件 SHA 相同只能证明字节重复；不同编码、命名、裁切的同一段画面仍可能重复。视觉指纹只筛候选，再对照至少多个对应时刻、击杀顺序及 HUD；相同地图、同一站位不足以删去素材。优先保留覆盖完整、画质合适的版本，不一律选更长文件。范围接回后重新检查包含关系，避免把早一杀单独再交付。不同交战只有上下文重叠时，不因此误判为同一段击杀。

### 4. 稳定修订清单后编码

保留原扫描事件和历史回执，另存当前交付决定。每条至少记录：

```text
稳定 clip_id、源路径和源身份、原扫描指纹／回执
旧输出路径和哈希（如有）、最终 start/end
逐次可见击杀：源时间、人物、武器类别、画面证据
有时间校准时：原 scan_ts、适用区间、转换规则、对齐锚点
实际杀数、最终类别、决定原因、尚存疑点
最终目录和文件名、分类同义名映射
动作：保留／改名移动／重提／重复／并入另一条
被移出条目对应的保留 clip_id、目标路径
内容复核、媒体校验、播放试听、用户验收各自状态
```

以上字段使用 [prepare / deliver 清单](delivery.md) 保存和执行。已知候选事件的确认／排除仍可用 [事件复核](review.md)；未记录的新击杀直接写入有源图依据的最终 kills，错误视角边界在最终区间中修正，不伪造 event_id 或把原 OCR 改为“已识别”。历史清单先核对来源与字段后转换，不自动猜测字段含义。

冻结前将本次内容复核结论及依据回写当前清单，核对杀数、范围、类别和复核状态一致。仅分类移动时复用对应修订的既有内容依据，本次移动验证单独记录。

在导出前检查区间合法、源身份一致、实际杀数有证据、目标无冲突、被合并条目有保留版本。一个复核完成的小批可先冻结并导出；仍在修改的条目不要混入已排队版本。计划变化时明确作废旧任务，只重做受影响条目。

只改名字或文件夹时直接移动，保持字节哈希。范围变化时从原片准确重提；不要把已有短片当源文件补不存在的前后文。`copy` 不保证帧边界。可用已验证的硬件编码提速，但应保留显示尺寸／比例、帧率语义与音轨，并做真实样本校验；不要把硬件编码当作当前 CLI 已有的参数。

### 5. 分类移动与交付验证

- 编码前按样片输出码率估计临时文件和备份空间，选择容量足够的位置。不要等系统盘将满才搬整批。输出目录保持纯成片，证据与临时文件放独立运行目录。
- 分类默认落为 `YYYY-MM-DD/<武器大类>/*.mp4`。用户已有交付目录时沿用该批日期和根目录，将各类成片实际放入子文件夹，文件名包含类别、杀数、来源、源区间和短唯一标识。
- 同盘移动可保留原字节并省去大文件复制；跨盘复制完成后校验，再切换当前路径。保存旧片和旧索引的可恢复备份，不覆盖原录像。批量备份／替换遵循用户已经授权的范围。
- 开始移动前保存本次逐项清单和当前索引快照。清单包含 clip_id、旧／新路径、哈希、文件身份、类别及完成状态，并确认源、目标均在约定交付范围且目标无冲突。
- 每项移动成功并校验后写回状态。遇到文件占用，记录受影响项，继续独立可处理项，提示用户释放占用；从清单续移时先核验已完成项的目标身份和哈希依据。目标已存在时，只有与本次已完成映射一致才复用，其余保留冲突并报告。
- 哈希证据绑定路径、大小、mtime_ns 和实际验证时点。未改变内容的文件可复用有效验证；内容或身份变化后再重验。避免编码、搬迁、发布各阶段无条件全量重读同一份视频，也不能在复制尚未完成时标成功。
- 每条新增／复用文件检查流、时长、显示尺寸、首尾解码及应有音轨。选择本次改变过的格式、旋转、边界和合并场景，另做源时间对齐与完整解码；样本数量由覆盖场景决定，不机械沿用历史的 12 条。
- 文件就位后更新当前交付清单、扫描记录中的成片路径、`curated_delivery`／latest 指针及依赖路径的验证记录。原始历史回执保留，通过映射追溯旧路径。索引尚未全部提交时，将分类记录保持为进行中，恢复时依据逐项完成状态核对。
- 读取本次分类／修复回执，核对实际 MP4 集合与清单逐条一致、每类数量及总数相符、命名杀数正确、当前路径可访问，已完成项的旧交付路径已迁出。媒体验证及源画面证据绑定有效文件身份和字节哈希后可复用。只有全部目标就位且索引读回一致才记录完成，剩余占用、冲突或疑点单列。
- 汇报本次机器检查、源画面复核、实际播放／试听及用户验收的真实状态。完整解码不等于听过声音，静帧也不等于看过完整动作。未解决的内容疑点不能被媒体校验冲掉。

## 快速返修已有素材

1. 先定位用户例子，同时盘点本批当前交付。用输出 key、新旧路径映射或分类回执反查原路径和源时间；不要因为文件已移动就重新扫描。
2. 验证原文件身份及扫描指纹，读取已有 events、views、阶段与修订清单，列出短片尾、首端已有计数、邻近事件、分组断点、区间重叠和跨源重复候选。
3. 先复用已经提取的源帧。新增抽帧只覆盖可疑首尾、候选遗漏点及必要的相邻回合，采用“总览找位置 → 小窗口加密”的顺序；若间隔过大仍不清楚，再查看连续短窗口。不要仅围着已识别事件看图，否则永远找不到未识别事件。
4. 按前述四项复核修正，而非统一加杀数、加尾长或调大 kill-gap。源片本来缺失的动作不可补造；疑点写明。
5. 稳定当前修订清单后，仅重新编码范围改变的条目，其他条目复用。检查恢复的长片是否已经包含另一条旧片，再决定并入或保留。
6. 校验、备份、替换、更新当前索引并读回，完成后记录“本批已修复”。只有已授权且实际修改、测试了通用引擎，才可说检测程序已经修好。

只有源修订改变、扫描指纹失效或相关范围没有可用证据时才考虑重新扫描。优先限定到受影响文件；当前 CLI 没有任意时间段 OCR 重扫选项，不能假装已局部重扫。不因一个坏例子对整个素材库使用 `--rescan`。

## 2026-10 的实际教训

一次混合长短录像任务，初次交付 217 条。用户指出某条“2 杀”其实有三次 AWM 击杀，约发生在 7.667、10 和 13.5 秒。旧片在 13.833 秒结束；原片长 17.2 秒。问题同时涉及漏计和错误收尾，单纯重命名或加固定尾长不足以复核整批。

后续利用原缓存和局部源帧修订 146 条（144 条重新裁切、2 条仅改命名），修正 69 条杀数，移出 16 个重复副本，另将 2 条并入完整片段，最终保留 199 条。它证明该批修订已完成，不代表所有素材召回率，也没有证明通用检测引擎已修好。

本例中容易重复犯的错：只核对 OCR 已发现事件、把末端 HUD 总数当本片杀数、把编码成功当内容正确、分类与范围复核分开、先批量编码再补改清单，以及先放系统盘后因空间不足再次搬迁。使用上述流程是为了让这些问题在候选阶段暴露。
